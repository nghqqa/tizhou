## 1. 当前方案的真实瓶颈

现状：`tools/ocr-worker.py` 文字层优先 + RapidOCR 3.9.2 200DPI 兜底 +
RapidDoc 0.9.10 结构化（表格/图形）。95 页真实基准（[baseline.md](./baseline.md)）暴露：

1. **98.3% 页面没有可用文字层**，全量走 OCR；每页 0.8s（纯 OCR）/ 1.9s（结构化），
   DirectML 下峰值内存 1.6GB。
2. **静默丢题嫌疑 76 处/95 页**：题号被 OCR 误读（`11.`→`1.`、`l.`）后
   连续性断裂；现有题号保护正则防不住「OCR 认错」这一层。
3. **选项齐备代理仅 0.445**：分栏、跨行、图文混排的选项块在
   「逐行 OCR + 行过滤」范式下无法保证 A-D 完整。
4. **图形推理对文字 OCR 不可见**：图推页只产出孤立字母 `A/B/C`，
   图形本体丢失；RapidDoc 能给出 image regions（39 页 232 个），
   但真实版式是九宫格题干、①-⑥ 合并条带、整页讲解块——
   **bbox 级 A-D 选项绑定在这三种版式上都不可行**（详见 §4）。
5. **资料分析的无边框表格与图表数字流**：RapidDoc 39 页仅 11 个 table region；
   数字流混入正文已有隔离（`quarantineNumberStreamLine`），但表格数字精度无基线。
6. **水印长尾**：已知水印（`微信SKA\d+` 等）有白名单剥离，
   但实测页仍有「一手最全公考资源加微信SYA648」等新形态混入正文。
7. 重要事实：**生产 RapidOCR 用的识别/检测模型已是 PP-OCRv6 small（ONNX）**，
   「换 PP-OCRv6」不构成升级项；差异在版面/表格管线。

要点：

- **B 并没有「表格魔法」**：20 页资料分析 0 表格检出，图表被整体裁图
  （这反而符合「图表数字流不进正文」）；其代价是 125s/页、6.7GB 内存、
  踩坑安装，数字一致性也只有 0.52（图表页数字不可检索）。
- **C 的阅读序 markdown 和图片切分质量最好，但 7GB 模型、45s/页**，只适合离线对照。
- **VL 的部署成本实测**：需独立 paddle≥3.2 环境（与 B 的 paddle≤3.0 互斥）；
  PaddleOCR-VL-1.6 载入成功（init 53.7s）后，CPU 推理在本环境崩溃
  （`Exception from the 'vlm' worker`，worker 内部堆栈被吞，两页均复现）——
  离线部署成本被证实为「高风险高成本」，本轮不做进一步投入。
- 三者在「脏题本」上的共同短板：图形推理合并条带、无边框表、页眉水印治理
  与 A 是同一批问题，引擎更换不自动解决。

## 4. 实验结果（阶段4-8）

实验 worker（`exp_worker.py`，300DPI+灰度+去倾斜+CLAHE+算法版面分区）：

- 页面分类（确定性规则）：95 页全部产出类型 + 置信度；资料分析 20、图推候选 19、
  解析 25、普通文字 27、空白封面 4，与抽样预期一致。
- **无静默丢题不变量（14/14 回归测试通过）**：原始 OCR 行数守恒、
  题号集合零丢失、A-D 标记零丢失、数字流不进正文。
  这是比「平均置信度」更强的质量门，**建议移植进生产 import-quality**。
- 资料分析专用输出：12/20 页检出完整表格网格（HTML+JSON+单元格 bbox+置信度）、
  39 个图表区带原图裁剪与标签 OCR、数字异常告警 2 处、低置信度告警。
  实验中还抓到并修复了一个典型误判：**统计图的网格线会被当成表格**
  （31x6「完整表格」实为柱状图 y 轴刻度）——现已加「网格框与图片对象重叠 >50% 判为图表」规则；
  该类混淆正是资料分析必须保留人工核对的原因之一。
  **表格数字准确率未经人工核对，不声称达标**。
- 图形推理专用输出：19/19 页全部正确进入**人工审核**（0 强行绑定）。
  实测三种版式（九宫格题干、①-⑥合并条带、整页讲解块）证明 bbox 级
  A-D 绑定不可行；实现了 4 图一行 / 2x2 网格两种可绑定版式的规则，
  但真实样本未出现可绑定页——**图推自动高准确率本轮不存在，也不应声称**。
- 解析配对（阶段7）：
  - 数量关系600题 题本(1-8) × 花生解析册：**22/23 配对，0 错配**（1 条解析在窗口外）。
  - 四海判断推理 × 答案册（范围答案格「21-25 DACDD」734 条）：
    段标题映射成功；**题号读对的题 7/7 全部配对；OCR 误号题 32 条全部进「配对待确认」**。
  - 答案字母只来自解析册；题干从未被答案反向修正；
    答案重复认领、顺序偏离、字母数不符一律待确认。
- 资源台账：300DPI 全管线 ≈0.9-1.1s/页，峰值 ~945MB（见回归测试输出）。

## 5. 推荐的生产方案（分步、可回退）

1. **保留 RapidOCR 通道为唯一默认**（本轮不动）。
2. 低风险增强（不动引擎，只动解析层）：
   - 范围答案格正则允许**冒号缺省**（`21-25 DACDD`，生产 `ANSWER_RANGE` 现要求冒号）；
   - 把实验 worker 的**行数守恒/题号守恒不变量**加进 import-quality 作为导入质量门；
   - 水印白名单补录本轮新发现的形态（仍只删命中的宣传片段）。
3. 资料分析表格：B 专项（20 页）证明 PP-StructureV3 **没有表格检出优势**
   （0 表格区，图表整体裁图）。维持 RapidDoc 现状；
   若未来需要「图表整体裁图 + 干净阅读序」的版式，B 的输出形态可作参考，
   但 125s/页 + 6.7GB 内存不支持进生产。极少数复杂资料离线对照可用
   MinerU（可选组件形态，按需安装，产物仅作参考层与原图并列）。
4. 图推维持现状：默认人工审核（与生产 `GRAPHIC_AUTO_STRUCTURE.enabled=false` 一致）。
5. 人工标注落地后（annotation-template 95 页），用真实 GT 重跑本基准，
   达到「真实指标改善 + 静默丢题 0」才进入替换评审。

## 6. 必须保留人工审核的能力

- **图形推理全部**：规律判定、A-D 图片选项绑定、题干图/选项图归属；
- **无边框表格**与所有数字异常告警页（数字流、多小数点、全角数字）；
- **配对待确认**项（误号、低相似度、答案格字母数不符、答案重复认领）；
- 图表标签 OCR（坐标轴数字语义）；
- 水印剥离命中项的抽样（避免误删正文）。
